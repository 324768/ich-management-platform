  ---
  Omnitrix AI v2.0（重构后）vs Kortex AI 完整对比

  一、架构模式对比

  两者重构后都采用 LangChain4j 纯编排模式，但设计哲学有本质区别。

  1.1 编排模式

  Kortex AI:
    用户请求 → OrchestratorService
      → buildMasterBrain() [每次请求构建]
        → MasterBrain (LangChain4j AiService)
          → CompositeToolProvider
            ├── SystemSubAgentToolProvider (3个系统SubAgent)
            └── DynamicSubAgentToolProvider (数据库动态Agent)
          → SummarizingTokenWindowChatMemory
          → AiServiceListener (Langfuse + Prometheus + 日志)
      → masterBrain.chatStream()
      → LLM 自动 Function Calling 循环
      → 输出

  Omnitrix AI v2.0:
    用户请求 → OrchestratorService
      → 安全检查 (RateLimiter + GuardrailsFilter + TokenBudget)
      → MasterBrainFactory.buildBrain(role) [根据角色构建不同Brain]
        → UserMasterBrain / AdminMasterBrain / UltraMasterBrain
          → CompositeToolProvider (根据role过滤Tool集合)
            ├── SystemSubAgentToolProvider (真正的SubAgent)
            └── SimpleToolProvider (简单Tool)
          → ChatMemory (Redis)
          → Skill prompt 动态注入
          → 用户画像注入
      → masterBrain.chatStream()
      → LLM 自动 Function Calling 循环
      → 后处理 (记忆提取 + 遥测 + 成本追踪)

  核心区别: Kortex 是单一 MasterBrain，Omnitrix v2 是三套 MasterBrain（通过 Factory 模式差异化）。Omnitrix v2
  在编排前后多了安全检查和后处理两层，Kortex 没有。

  1.2 MasterBrain 构建方式

  ┌─────────────────┬───────────────────────────────────────────────────┬─────────────────────────────────────────────────────────┐
  │      维度       │                     Kortex AI                     │                    Omnitrix AI v2.0                     │
  ├─────────────────┼───────────────────────────────────────────────────┼─────────────────────────────────────────────────────────┤
  │ MasterBrain     │ 1个接口                                           │ 3个接口（User/Admin/Ultra）                             │
  │ 数量            │                                                   │                                                         │
  ├─────────────────┼───────────────────────────────────────────────────┼─────────────────────────────────────────────────────────┤
  │ 构建方式        │ buildMasterBrain() 单一方法                       │ MasterBrainFactory.buildUserBrain/AdminBrain/UltraBrain │
  ├─────────────────┼───────────────────────────────────────────────────┼─────────────────────────────────────────────────────────┤
  │ System Prompt   │ Langfuse → Nacos → 代码常量（三级回退）           │ 代码 @SystemMessage + Skill 动态注入 + 用户画像注入     │
  │ 来源            │                                                   │                                                         │
  ├─────────────────┼───────────────────────────────────────────────────┼─────────────────────────────────────────────────────────┤
  │ Tool 集合       │ 所有 Agent 统一注册，通过权限过滤                 │ 按 role 预过滤，不同 Brain 看到不同 Tool 集合           │
  ├─────────────────┼───────────────────────────────────────────────────┼─────────────────────────────────────────────────────────┤
  │ 记忆            │ SummarizingTokenWindowChatMemory（Token           │ MessageWindowChatMemory + 外部 MemorySummarizer         │
  │                 │ 阈值触发摘要）                                    │                                                         │
  ├─────────────────┼───────────────────────────────────────────────────┼─────────────────────────────────────────────────────────┤
  │ Listener        │ Langfuse + Prometheus + 日志（三合一）            │ 自建 ObservabilityListener + MetricsListener            │
  └─────────────────┴───────────────────────────────────────────────────┴─────────────────────────────────────────────────────────┘

  分析: Kortex 的 Prompt 管理更灵活（Langfuse 支持热更新 + 多租户覆盖 + A/B 测试），Omnitrix v2 的 Prompt 管理更简单直接（代码 + Skill
   注入）。Kortex 的记忆系统更智能（Token 阈值自动摘要 + 工具结果压缩），Omnitrix v2 的记忆系统更丰富（多了用户画像长期记忆）。

  ---
  二、SubAgent 体系对比

  这是两者最大的差异点。

  2.1 SubAgent 数量与定位

  Kortex AI:
    SystemSubAgent (3个):
      ├── MailSystemSubAgent      → 邮件搜索/阅读/回复
      ├── DocumentSystemSubAgent  → 文库搜索/文档操作
      └── GeneralToolsSubAgent    → 网络搜索/Artifact/翻译/代码执行

    DynamicSubAgent (N个):
      └── 数据库配置的自定义Agent (带知识库)

  Omnitrix AI v2.0:
    SystemSubAgent (8个):
      ├── ContentSystemSubAgent        → 非遗内容（13个内部工具）
      ├── CommerceSystemSubAgent       → 文创商城（11个内部工具）
      ├── UserSystemSubAgent           → 用户服务
      ├── AdminSystemSubAgent          → 管理操作
      ├── AdminActionSystemSubAgent    → 管理写操作
      ├── UserAiMetaSystemSubAgent     → Ultra: 用户端AI元管理
      ├── AdminAiMetaSystemSubAgent    → Ultra: 管理端AI元管理
      └── UltraCrossUserSystemSubAgent → Ultra: 跨用户操作

    SimpleTool (10+个):
      ├── KnowledgeSearchTool    → 知识库搜索
      ├── RecommendTool          → 推荐
      ├── BrowseHistoryTool      → 浏览记录
      ├── GeneralChatTool        → 通用闲聊
      ├── AdminDataQueryTool     → 管理数据查询
      ├── UltraUserControlTool   → Ultra: 用户控制
      ├── UltraSystemTool        → Ultra: 系统管理
      ├── UltraAnalyticsTool     → Ultra: 数据分析
      ├── UltraSecurityTool      → Ultra: 安全审核
      └── UltraSkillControlTool  → Ultra: Skill管理

    DynamicSubAgent (N个):
      └── 数据库配置的自定义Agent

  分析: Kortex 的 SubAgent 少而精（3个系统 + N个动态），每个 SubAgent 覆盖一个大的功能域。Omnitrix v2 的 SubAgent 多而专（8个系统 +
  10+ SimpleTool + N个动态），按业务域和权限精细划分。Omnitrix v2 额外引入了 SimpleTool 概念（Kortex 没有这个区分，所有都是
  SubAgent）。

  2.2 SubAgent 内部结构

  ┌────────────┬───────────────────────────────────────────────────────────┬───────────────────────────────────────────────────────┐
  │    维度    │                         Kortex AI                         │                   Omnitrix AI v2.0                    │
  ├────────────┼───────────────────────────────────────────────────────────┼───────────────────────────────────────────────────────┤
  │ 内部 LLM   │ 有（AgentRuntime，独立的 LangChain4j AiService）          │ 有（内部 AgentRuntime，独立的 LangChain4j AiService） │
  ├────────────┼───────────────────────────────────────────────────────────┼───────────────────────────────────────────────────────┤
  │ 内部工具   │ 有（如 MailSystemSubAgent 有搜索/阅读/回复工具）          │ 有（如 CommerceSystemSubAgent 有 11 个 @Tool 方法）   │
  ├────────────┼───────────────────────────────────────────────────────────┼───────────────────────────────────────────────────────┤
  │ 知识库集成 │ AgentRuntime 自动注入 KnowledgeSearchTool                 │ DynamicSubAgent 绑定知识库                            │
  ├────────────┼───────────────────────────────────────────────────────────┼───────────────────────────────────────────────────────┤
  │ 独立记忆   │ 有（独立 memoryId: userId:sessionId:sub-agent:agentCode） │ 有（类似设计）                                        │
  ├────────────┼───────────────────────────────────────────────────────────┼───────────────────────────────────────────────────────┤
  │ 上下文传播 │ BaseToolContext + LangfuseTraceContext                    │ AgentContext                                          │
  └────────────┴───────────────────────────────────────────────────────────┴───────────────────────────────────────────────────────┘

  分析: 两者的 SubAgent 内部结构几乎一致 — 都是独立的 LangChain4j AiService，有自己的工具集和记忆。核心区别在于 Kortex 的 SubAgent 有
  Langfuse 追踪链路传播，Omnitrix v2 用自建的 AgentContext。

  2.3 SubAgent 执行流程

  Kortex AI:
    MasterBrain → Function Call → SystemSubAgentToolProvider.execute()
      → SubAgentTool.execute()
        → 解析参数 (user_query, context, show_result_to_user)
        → 清洗 context（移除控制字符 + 截断超长内容）
        → 构建子 Agent 独立会话 ID
        → 传播上下文 (BaseToolContext + LangfuseTraceContext)
        → 推送 agent_dispatch 事件
        → agentRuntime.chat() 执行
        → show_result_to_user=true → SSE 直推
        → SubAgentResultWrapper.wrap() 包装结果
      → 返回 XML 给 MasterBrain

  Omnitrix AI v2.0:
    MasterBrain → Function Call → SystemSubAgentToolProvider.execute()
      → 找到对应 SystemSubAgent
      → agent.execute(query, context, showResultToUser=true)
        → 内部 AgentRuntime (LangChain4j) 执行
        → 内部 LLM 选择工具 → 执行业务逻辑
        → showResultToUser=true → SSE 直推
        → 生成摘要 + Hint
        → 返回 SubAgentResult
      → result.toXml() 返回给 MasterBrain

  分析: 流程几乎一致。关键区别：
  1. Kortex 的 SubAgentTool 有 context 清洗（移除控制字符 + 截断超长内容），这是一个重要的防御性设计，Omnitrix v2 应该借鉴
  2. Kortex 推送 agent_dispatch 事件通知前端"正在调度哪个 Agent"，Omnitrix v2 也应该有
  3. Kortex 的 SubAgentResultWrapper 更成熟（状态检测优先级、连续重试计数、多种 Hint 策略），Omnitrix v2 的 SubAgentResult 相对简单

  三、结果处理机制对比

  3.1 SubAgentResultWrapper vs SubAgentResult

  ┌────────────────┬─────────────────────────────────────────────────────────────────┬───────────────────────────────────────────┐
  │      维度      │                Kortex AI (SubAgentResultWrapper)                │     Omnitrix AI v2.0 (SubAgentResult)     │
  ├────────────────┼─────────────────────────────────────────────────────────────────┼───────────────────────────────────────────┤
  │ 状态检测       │ 6级优先级（CLARIFICATION_SENT → partial → error → 结构化数据 →  │ 3级（success / empty / error）            │
  │                │ empty → success）                                               │                                           │
  ├────────────────┼─────────────────────────────────────────────────────────────────┼───────────────────────────────────────────┤
  │                │ 10+ 种条件组合（awaiting_user, 调用耗尽, 连续3+次empty,         │ 3种（success → task_completeness_review,  │
  │ Hint 策略      │ 连续2次empty, 长文档完成, 批量处理, 任务完整性审查, 继续完成,   │ empty → change_strategy, error → stop）   │
  │                │ 配置错误, 扩大搜索...）                                         │                                           │
  ├────────────────┼─────────────────────────────────────────────────────────────────┼───────────────────────────────────────────┤
  │ 连续重试计数   │ 有（consecutiveEmptyOrError 计数器）                            │ 无                                        │
  ├────────────────┼─────────────────────────────────────────────────────────────────┼───────────────────────────────────────────┤
  │ 原始请求追踪   │ 有（ORIGINAL_REQUEST 字段，用于任务完整性审查）                 │ 无                                        │
  ├────────────────┼─────────────────────────────────────────────────────────────────┼───────────────────────────────────────────┤
  │ shown_to_user  │ 有（告诉 MasterBrain 数据已推送给用户）                         │ 无                                        │
  │ 标记           │                                                                 │                                           │
  ├────────────────┼─────────────────────────────────────────────────────────────────┼───────────────────────────────────────────┤
  │ 输出格式       │ XML（含 status, agent, call_number, shown_to_user, summary,     │ XML（含 status, agent, summary, hint）    │
  │                │ data, hint）                                                    │                                           │
  └────────────────┴─────────────────────────────────────────────────────────────────┴───────────────────────────────────────────┘

  分析: Kortex 的 SubAgentResultWrapper 明显更成熟。特别是：
  1. 连续重试计数 — 防止 MasterBrain 无限循环调用失败的 Agent
  2. ORIGINAL_REQUEST 追踪 — 让 MasterBrain 能对照原始请求逐条审查任务完成度
  3. shown_to_user 标记 — 告诉 MasterBrain "数据已经展示给用户了，你只需要简短点评"
  4. CLARIFICATION_SENT 状态 — 当 SubAgent 向用户发送了澄清问题时，MasterBrain 应该立即停止

  Omnitrix v2 应该补齐这些能力。

  3.2 show_result_to_user 机制

  ┌──────────────────┬───────────────────────────────────────────────────────────┬────────────────────────────────┐
  │       维度       │                         Kortex AI                         │        Omnitrix AI v2.0        │
  ├──────────────────┼───────────────────────────────────────────────────────────┼────────────────────────────────┤
  │ 参数来源         │ MasterBrain 的 Function Call 参数（LLM 自己决定是否直推） │ SubAgent 执行时固定 true       │
  ├──────────────────┼───────────────────────────────────────────────────────────┼────────────────────────────────┤
  │ 推送事件         │ agent_result 事件                                         │ agent_result 事件              │
  ├──────────────────┼───────────────────────────────────────────────────────────┼────────────────────────────────┤
  │ MasterBrain 感知 │ XML 中 shown_to_user="true" 告知 MasterBrain              │ 无显式标记                     │
  ├──────────────────┼───────────────────────────────────────────────────────────┼────────────────────────────────┤
  │ 前端处理         │ 前端收到 agent_result 直接渲染                            │ 前端收到 agent_result 直接渲染 │
  └──────────────────┴───────────────────────────────────────────────────────────┴────────────────────────────────┘

  分析: Kortex 的设计更优 — show_result_to_user 是 MasterBrain 的 Function Call 参数之一，由 LLM 自己决定是否直推。这意味着 LLM
  可以根据场景判断：有些结果适合直推（搜索结果列表），有些不适合（中间计算结果）。Omnitrix v2 固定 true 不够灵活。

  四、记忆系统对比

  ┌─────────────────┬───────────────────────────────────────────────────────┬─────────────────────────────────────────────────┐
  │      维度       │                       Kortex AI                       │                Omnitrix AI v2.0                 │

  ├─────────────────┼───────────────────────────────────────────────────────┼─────────────────────────────────────────────────┤

  ├─────────────────┼───────────────────────────────────────────────────────┼─────────────────────────────────────────────────┤
  │ 系统记忆        │ 无                                                    │ SystemMemoryService（系统全局记忆）             │
  ├─────────────────┼───────────────────────────────────────────────────────┼─────────────────────────────────────────────────┤
  │ 记忆 TTL        │ 24 小时                                               │ 可配置                                          │
  └─────────────────┴───────────────────────────────────────────────────────┴─────────────────────────────────────────────────┘

  分析:
  - Kortex 的会话记忆更智能（Token 阈值自动摘要 + 工具结果压缩 + 中文感知 + 一致性自愈）
  - Omnitrix v2 的长期记忆更丰富（用户画像 + 系统全局记忆，Kortex 完全没有）
  - 两者互补：Omnitrix v2 应该借鉴 Kortex 的工具结果压缩和中文 Token 估算

  七、Prompt 管理对比

  十五、最终结论

  重构后的 Omnitrix AI v2.0 和 Kortex AI 在编排模式上完全一致（都是 LangChain4j 纯编排），LLM
  调用效率也完全一致。两者的核心差异不在架构层面，而在业务定位和基础设施成熟度：

  - Kortex 强在基础设施: Langfuse 追踪/评估/Prompt 管理、Prometheus 指标、SubAgentResultWrapper 的成熟度、context
  安全清洗、工具结果压缩。这些都是"做得更精细"的体现。
  - Omnitrix v2 强在业务能力: 三层权限体系、Skill 动态增强、PendingAction 写操作确认、用户画像长期记忆、Token 预算/熔断器/PII
  脱敏等企业级安全、24+ 垂直业务工具。这些都是"做得更深入"的体现。

  简单说：Kortex 是一个精致的通用 AI 编排框架，Omnitrix v2 是一个功能完备的垂直业务 AI 系统。重构后 Omnitrix v2
  补齐了编排模式的短板，同时保留了所有业务优势，综合能力超过 Kortex。但在基础设施精细度上（特别是可观测性和 Hint 机制），仍有向 Kortex
   学习的空间。
