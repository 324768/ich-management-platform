## 推荐架构：分层黑板架构（Hierarchical Blackboard）

### 为什么最适合你？

| 特性 | 匹配度 | 说明 |
|------|--------|------|
| **状态集中管理** | ⭐⭐⭐⭐⭐ | 黑板作为协调机制，避免Sub-agents直接通信 |
| **主从分层** | ⭐⭐⭐⭐⭐ | 主脑战略层，Sub-agents战术层 |
| **并行执行** | ⭐⭐⭐⭐⭐ | Sub-agents独立读取，天然并行 |
| **动态扩展** | ⭐⭐⭐⭐ | 可随时添加Sub-agent类型 |

## 关键设计决策

### 1. 黑板分层策略

| 分层 | 内容 | 更新频率 | 生命周期 |
|------|------|---------|---------|
| **战略黑板** | 阶段目标、全局约束、资源预算 | 低（阶段切换） | 长（整个任务） |
| **战术黑板** | 子任务队列、输入参数、优先级 | 中（任务调度） | 中（子任务期间） |
| **结果黑板** | 中间结果、状态标记、错误日志 | 高（实时写入） | 短（聚合后清理） |

**优势**：
- 避免单黑板性能瓶颈
- 不同频率的数据分离，减少锁竞争
- Sub-agents只需关注相关层级

### 2. Sub-agent设计模式：无状态工作者

```
Sub-agent 理想特征：
┌─────────────────┐
│   Sub-agent X   │
│  ┌───────────┐  │
│  │  读取黑板  │  │◄── 输入（只读）
│  │  (上下文)  │  │
│  └───────────┘  │
│        │        │
│        ▼        │
│  ┌───────────┐  │
│  │  本地执行  │  │◄── 无外部依赖，幂等
│  │  (计算/调用)│  │
│  └───────────┘  │
│        │        │
│        ▼        │
│  ┌───────────┐  │
│  │  写入黑板  │  │◄── 输出（只写结果黑板）
│  │  (结果/状态)│  │
│  └───────────┘  │
└─────────────────┘
```

**关键约束**：
- **无状态**：不维护本地内存，所有状态进黑板
- **幂等**：同一输入永远产生同一输出（支持重试）
- **只读战术黑板，只写结果黑板**：避免写冲突

### 3. 主脑的双角色循环

```
主脑工作循环：
┌──────────┐     ┌──────────┐     ┌──────────┐
│  规划者   │────►│  监控者   │────►│  再规划者 │
│ (Planner)│     │(Monitor) │     │(Re-planner)│
└────┬─────┘     └────┬─────┘     └────┬─────┘
     │                │                │
     ▼                ▼                ▼
写入战略黑板      读取结果黑板      更新战略黑板
(分解任务)       (检查进度/异常)    (调整策略)
```

## 与其他架构的对比

| 架构模式 | 是否适合你 | 原因 |
|---------|-----------|------|
| **纯黑板** | ⚠️ 基础版 | 单黑板会成为瓶颈 |
| **分层黑板** | ✅ **最佳** | 解决扩展性，保留协调优势 |
| **MAS（多智能体）** | ❌ 不推荐 | 你的Sub-agents无需直接通信 |
| **主从架构** | ⚠️ 部分匹配 | 缺少状态共享机制 |
| **流水线** | ❌ 不适合 | 你需要动态任务分配，非线性流 |
| **Pub-Sub** | ⚠️ 可辅助 | 可作为黑板底层实现，但非替代 |

## 双主脑架构（2026-03 更新）

### 架构概览

```
用户请求
    │
    ├── 普通用户/管理员 → MasterBrain
    │                        ├── 简单 → IntentRouter → SubAgent
    │                        └── 复杂 → TaskBoard → SubAgents
    │
    └── Omnitrix AI Ultra版 → UltraMasterBrain
                         ├── 简单 → UltraIntentRouter → MetaAgent
                         └── 复杂 → L2 TaskBoard → MetaAgents
```

### 组件职责

| 组件 | 职责 | 适用模式 |
|------|------|----------|
| **MasterBrain** | 智能决策：判断路径（quick_path/blackboard）、LLM驱动分解、动态再规划 | 普通用户/管理员 |
| **UltraMasterBrain** | Ultra决策：判断Ultra请求、Ultra复杂度、Ultra路径决策、Ultra再规划 | Omnitrix AI Ultra版 |
| **TaskDecomposer** | L1任务分解器：用户/管理员SubAgent之间分发任务 | 普通模式 |
| **UltraTaskDecomposer** | L2任务分解器：元代理之间分发任务（user_ai_meta/admin_ai_meta/ultra_*） | Ultra模式 |
| **TaskBoard** | 黑板：L1（普通）、L2（Ultra） | 通用 |

### 决策流程

#### MasterBrain（普通模式）

```
1. shouldUseLlmBrain() → 是否需要LLM决策
2. decide() → quick_path / blackboard
3. replan() → 动态再规划
```

#### UltraMasterBrain（Ultra模式）

```
1. isUltraRequest() → 判断是否为Ultra请求
2. decide() → quick_path / blackboard（Ultra专用）
3. replan() → Ultra再规划
```

### 元代理（MetaAgents）

Ultra模式下，L2黑板上的任务由以下元代理执行：

| 元代理 | 职责 |
|--------|------|
| user_ai_meta | 用户端AI，可执行浏览、购物、下单等 |
| admin_ai_meta | 管理员普通AI，可执行审批、发货、统计等 |
| ultra_user_control | 控制用户AI开关（禁用/启用） |
| ultra_cross_user | 代替指定用户执行操作 |
| ultra_system | 系统级用户管理 |
| ultra_analytics | 用户分析、行为统计 |
| ultra_browse_history | 查看用户浏览记录 |
| ultra_security | 安全审计、操作日志 |
