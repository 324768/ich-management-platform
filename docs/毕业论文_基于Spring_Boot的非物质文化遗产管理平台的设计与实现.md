# 基于Spring Boot的非物质文化遗产管理平台的设计与实现

## 摘要

随着互联网技术的飞速发展和人工智能技术的日益成熟，传统文化保护与传播正在经历数字化转型。非物质文化遗产作为中华民族优秀传统文化的重要组成部分，其保护与传承具有历史意义和现实价值。然而，传统管理方式存在信息分散、传播渠道有限、互动性不足等问题，难以满足现代用户对文化体验的需求。

本文设计并实现了一个基于Spring Boot框架的非物质文化遗产管理平台。该平台采用微服务架构，整合传统电商功能与人工智能技术，为用户提供全方位的非遗文化服务。系统采用Apache Dubbo作为微服务框架，Zookeeper作为注册中心，MySQL作为数据存储，Redis作为缓存，并创新性地引入Omnitrix AI智能助手模块，实现智能问答与个性化推荐等功能。

本文详细阐述系统的需求分析、系统设计、数据库设计、功能模块实现以及系统测试等全过程。系统实现用户端和管理端两大功能模块，涵盖非遗文化浏览、传承人查询、文创商品购买、订单管理、AI智能问答等核心功能。系统成功为非遗文化数字化传播提供新方案，具有实用价值和推广意义。

**关键词**：非物质文化遗产；Spring Boot；微服务；Dubbo；人工智能

---

## ABSTRACT

With the rapid development of Internet technology and the increasing maturity of artificial intelligence technology, the protection and dissemination of traditional culture is undergoing digital transformation. As an important part of China's excellent traditional culture, intangible cultural heritage protection and inheritance have important historical significance and practical value. However, traditional intangible cultural heritage management methods have problems such as scattered information, limited dissemination channels, and insufficient interactivity, making it difficult to meet modern users' needs for cultural experience.

This paper designs and implements a Spring Boot-based Intangible Cultural Heritage Management Platform, which adopts a microservice architecture and integrates traditional e-commerce functions with artificial intelligence technology to provide users with comprehensive intangible cultural heritage services. The system uses Apache Dubbo as the microservice framework, Zookeeper as the registry, MySQL for data storage, Redis for caching, and innovatively introduces the Omnitrix AI intelligent assistant module, achieving intelligent Q&A, personalized recommendation, and other functions.

This paper elaborates on the entire process of system requirements analysis, system design, database design, functional module implementation, and system testing. The system implements two major functional modules: user terminal and management terminal, covering core functions such as intangible cultural heritage browsing, inheritor queries, cultural product purchases, order management, and AI intelligent Q&A. The successful implementation of the system provides a new solution for the digital dissemination of intangible cultural heritage, with important practical value and promotional significance.

**Keywords**: Intangible Cultural Heritage; Spring Boot; Microservices; Dubbo; Artificial Intelligence

# 第1章 绪论

## 1.1 研究背景

在信息技术高速发展的今天，互联网已经渗透到社会生活的方方面面，深刻改变人们的生活方式和工作模式。随着“互联网+”战略的提出，各行各业都在积极探索与互联网深度融合的发展路径，传统文化领域也不例外。非物质文化遗产是中华民族五千年文明的重要组成部分，承载着丰富的历史信息和文化内涵，是中华民族的精神瑰宝。

然而，当前非物质文化遗产的保护与传播面临诸多挑战。传统非遗文化的管理方式主要依赖纸质档案和人工管理，信息分散、查询不便，难以形成系统化的知识体系。传播渠道相对有限，主要依靠博物馆展览、文化活动等线下方式，覆盖面窄、互动性差。年轻一代对非遗文化认知和了解不足，缺乏有效的途径去接触和体验非遗文化的魅力。非遗文化的传承面临人才断层的问题，许多传统技艺面临失传风险。

随着Web应用技术的不断成熟和人工智能技术的快速发展，为解决上述问题提供了新的思路。通过构建集非遗文化展示、传承人介绍、文创商品销售、智能问答服务于一体的综合性平台，可以有效整合非遗文化资源，拓宽传播渠道，提升用户体验，为非遗文化的保护与传承开辟新的路径[2]。

本课题正是基于这样的背景提出的，旨在设计并实现功能完善、体验良好的非物质文化遗产管理平台，为非遗文化数字化传播贡献力量。

## 1.2 研究目的及意义

### 1.2.1 研究目的

本研究的主要目的是设计并实现基于Spring Boot框架的非物质文化遗产管理平台，具体目标包括以下几个方面。

构建一套完整的非遗文化信息管理系统，实现非遗项目、传承人、非遗活动等信息的规范化管理和便捷查询。通过数据库技术将分散的非遗文化资源进行整合，形成系统化的知识库，方便用户快速获取所需信息。

建设一个文创商品交易平台，为非遗文化的产业化发展提供支撑。通过电商功能模块，实现文创商品的展示、搜索、购买、支付、订单管理等完整购物流程，促进非遗文化的商业化运营。

引入人工智能技术，打造智能化的用户服务体验。通过AI智能助手模块，为用户提供24小时的智能问答服务，解答关于非遗文化的问题，并根据用户偏好提供个性化推荐，提升用户黏性和满意度。

实现用户端和管理端分离的系统架构，满足不同角色用户的操作需求。用户端面向普通消费者，提供浏览、购买、咨询等服务；管理端面向运营人员，提供内容管理、订单处理、数据统计等功能。

### 1.2.2 研究意义

本研究的意义主要体现在理论价值和实践价值两个方面。

从理论价值角度来看，本研究将软件工程的理论方法应用于非遗文化管理领域，完成了从需求分析、系统设计到实现测试的完整软件开发流程，为类似的文化类应用系统开发提供参考范例。同时，本研究将人工智能技术与传统Web应用进行深度融合，探索AI技术在文化传播领域的应用模式，具有一定的学术探索意义。

从实践价值角度来看，本研究实现的非物质文化遗产管理平台具有重要的应用价值。平台能够有效整合非遗文化资源，解决信息分散、查询困难的问题，提升非遗文化的管理效率。平台拓宽非遗文化的传播渠道，通过互联网让更多人了解和接触非遗文化，增强公众对非遗文化的认知和认同。平台的文创电商功能为非遗文化的产业化发展提供新渠道，有助于非遗文化的可持续传承。AI智能助手模块的应用提升用户体验，为用户提供便捷、高效的个性化服务[8]。

## 1.3 国内外研究现状

### 1.3.1 国内研究现状

在国内，随着国家对传统文化保护工作的重视程度不断提升，越来越多的学者和机构开始关注非遗文化的数字化保护与传播工作。

在非遗数字化保护方面，国内已经建立多个国家级和省级的非物质文化遗产数据库。例如，中国非物质文化遗产网作为官方权威平台，收录大量非遗项目的文字、图片、视频等资料。然而，这些数据库主要以信息展示为主，功能相对单一，缺乏交互性和商业化运营能力。

在非遗类应用开发方面，国内市场上涌现出一些专注于非遗文化传播的移动应用，如“知味中国”“非遗之旅”等。这些应用在非遗文化展示方面做得较为出色，但在智能化服务、电商功能等方面仍有较大提升空间。

在技术研究方面，国内学者对传统文化数字化进行深入探讨。张宇航等人在《基于SpringBoot的微服务架构设计与实现》中探讨Spring Boot技术在信息系统中的应用[1]；李明华等人在《非物质文化遗产数字化保护平台的设计与实现》中研究数字化保护平台的设计方法[2]。这些研究成果为本系统的开发提供技术参考。

现有非遗类系统仍存在以下不足：功能集成度不高，展示、交易、互动等功能分散在不同的平台；智能化程度有限，缺乏智能问答和个性化推荐能力；用户体验有待提升，交互设计和视觉呈现不够现代；系统架构相对传统，缺乏对微服务等先进架构的应用。

### 1.3.2 国外研究现状

许多发达国家在文化遗产数字化保护方面起步较早，形成较为成熟的技术体系和运营模式。

在欧洲，许多国家建立完善的文化遗产数字化平台。例如，欧盟的Europeana平台整合来自欧洲各国博物馆、图书馆、档案馆的数字文化资源，提供丰富的文化遗产检索服务。在技术层面，该平台采用先进的语义网技术，实现跨语言、跨领域的知识关联。

在日本，传统文化保护与数字化技术的结合堪称典范。日本国立西洋美术馆等机构通过虚拟现实（VR）、增强现实（AR）技术，让用户能够沉浸式体验文化遗产的魅力。同时，日本在传统工艺的电商化运营方面也有成熟的经验，如乐天市场等平台设有专门的传统工艺品专区。

在韩国，政府大力推动传统文化与现代科技的融合。韩国传统文化振兴院开发的“非遗Live”平台，通过直播、短视频等新媒体形式传播非遗文化，取得了良好的效果。同时，韩国在传统文化主题的移动应用开发方面也积累了丰富经验。

从技术趋势来看，国外文化遗产数字化呈现以下特点：重视用户体验，强调交互性和沉浸感；广泛应用人工智能技术，如智能推荐、智能翻译、智能问答等；注重跨界融合，将文化内容与电商、旅游、教育等领域深度结合；采用先进的软件架构，如微服务、云原生等[14]。

综上所述，国内外在非遗文化数字化方面已经取得一定成果，但仍存在功能单一、智能化不足等问题。本研究将在借鉴国内外先进经验的基础上，设计并实现功能完善、智能化的非物质文化遗产管理平台。

# 第2章 相关技术、理论原理

## 2.1 Spring Boot框架

Spring Boot是Spring家族中的重要成员，它的设计目标是简化Spring应用的初始搭建以及开发过程。Spring Boot通过“约定优于配置”的理念，让开发者能够快速构建独立的、生产级别的Spring应用程序。

Spring Boot的主要特点包括：提供自动配置功能，能够根据类路径中的依赖自动配置Spring应用，大大减少配置文件的工作量；内置Tomcat、Jetty等Servlet容器，开发者可以直接运行Jar包形式的应用程序，无需额外部署War包；提供丰富的Starter组件，这些组件封装常用的技术框架配置，开发者只需引入相关依赖即可快速集成[11]。

本系统采用Spring Boot 3.2.5版本，该版本基于Java 17构建，提供更好的性能和更多的企业级特性。Spring Boot 3.x系列引入对GraalVM原生编译的支持，能够构建更轻量级的容器镜像，同时对响应式编程提供更好的支持。

Spring Boot的自动配置原理是通过@EnableAutoConfiguration注解实现的。该注解会扫描classpath中的jar包，根据jar包中的spring.factories文件，加载对应的自动配置类。这些自动配置类会检查应用是否引入了特定的依赖，如果引入了，则自动配置相应的Bean。这种机制大大简化开发者的配置工作，让开发者能够更专注于业务逻辑的实现。

## 2.2 Dubbo微服务框架

Apache Dubbo是一款高性能、轻量级的开源Java微服务框架，提供RPC通信、服务治理、服务注册与发现、负载均衡、容错等企业级功能。Dubbo最初由阿里巴巴开发并开源，后来成为Apache顶级项目，目前已被广泛应用于国内外的微服务架构中[9]。

Dubbo的核心架构包括四个角色：Provider（服务提供者）、Consumer（服务消费者）、Registry（注册中心）和Monitor（监控中心）。服务提供者启动时向注册中心注册自己的服务，服务消费者从注册中心订阅所需服务，注册中心负责服务元数据的管理和通知。监控中心负责统计服务调用次数、调用时间等监控数据。

Dubbo支持多种序列化方式，包括Hessian、JSON、Kryo、FST等，开发者可以根据性能和兼容性需求选择合适的序列化方式。在负载均衡方面，Dubbo提供了随机、轮询、最少活跃调用、一致性哈希等多种负载均衡策略。在容错方面，Dubbo支持失败自动切换、失败快速返回、失败安全等多种容错机制。

本系统采用Dubbo 3.2.19版本，该版本引入基于gRPC的Triple协议，提供更好的性能和跨语言支持。同时，Dubbo 3.x版本对服务发现进行优化，支持应用级服务发现，能够更好地适配云原生环境。

### 2.2.1 Zookeeper注册中心

Zookeeper是Dubbo默认使用的注册中心组件，是一个开源的分布式协调服务，能够为分布式应用提供一致性服务。

Zookeeper的数据模型采用树形结构，每个节点称为Znode，每个Znode可以存储少量数据，并可以拥有子节点。Znode分为持久节点和临时节点两种类型，临时节点在客户端断开连接后会自动删除，非常适合用于服务注册与发现场景。

在Dubbo中，Zookeeper的作用主要包括：服务注册，服务提供者启动时在Zookeeper上创建临时节点，记录服务地址；服务订阅，服务消费者启动时订阅感兴趣的服务，Zookeeper会推送服务变更通知；元数据存储，存储服务的版本、分组、权重等元数据信息[12]。

本系统的Zookeeper配置地址为zookeeper://127.0.0.1:2181，在生产环境中会根据实际部署情况进行相应调整。

## 2.3 Vue.js前端框架

Vue.js是一套渐进式JavaScript框架，用于构建用户界面。与其他大型框架不同，Vue.js采用自底向上的增量开发设计，核心库只关注视图层，易于上手，同时配合丰富的生态系统可以快速构建复杂的单页应用[3]。

Vue.js的主要特点包括：采用响应式数据绑定机制，当数据发生变化时，视图会自动更新，开发者无需手动操作DOM；提供组件化开发能力，可以将页面拆分为多个独立、可复用的组件，每个组件维护自己的状态和模板；指令系统非常强大，v-if、v-for、v-bind、v-on等指令让模板编写更加简洁。

Vue 3是Vue.js的最新版本，采用Proxy替代Object.defineProperty来实现响应式，解决Vue 2中数组变动的检测问题。同时，Vue 3对TypeScript提供更好的支持，引入Composition API，使得逻辑复用和代码组织更加灵活。

在状态管理方面，Vue.js通常配合Pinia或Vuex使用。Pinia是Vue官方推荐的状态管理库，比Vuex更轻量、更简单，支持TypeScript，提供模块化的状态管理能力。

本系统的前端采用Vue 3 + Pinia的技术栈，通过组件化的开发方式，实现了良好的用户界面和交互体验。

## 2.4 MySQL数据库

MySQL是开源关系型数据库管理系统的代表，具有体积小、速度快、成本低等优点，被广泛应用于各类Web应用中。MySQL支持多种存储引擎，其中InnoDB是默认的存储引擎，支持事务、行级锁定和外键约束[4]。

MySQL 8.0引入许多新特性，包括窗口函数、CTE（公共表表达式）、JSON增强等，这些特性能够简化复杂查询的实现。同时，MySQL 8.0对性能进行优化，提供更好的并发处理能力。

在数据库设计方面，本系统遵循以下原则：表名和字段名采用小写下划线命名法；主键统一使用bigint类型的自增ID；使用datetime类型存储时间字段；为常用查询条件创建适当的索引；采用逻辑删除而非物理删除，便于数据恢复。

本系统使用MySQL 8.0.33版本，根据业务划分了多个数据库：user_center（用户中心）、order_center（订单中心）、product_center（商品中心）、content_center（内容中心）、system_manage（系统管理）、common_db（公共库）和ai_service（AI服务）。

## 2.5 Redis缓存

Redis是一个开源的内存数据结构存储系统，可以用作数据库、缓存和消息队列。Redis支持多种数据类型，包括字符串、哈希、列表、集合、有序集合等，能够满足不同的业务需求[5]。

Redis的主要应用场景包括：将频繁访问的数据存储在Redis中，减轻数据库压力；存储用户登录状态，实现分布式会话；利用List或Stream实现异步任务处理；利用原子操作实现高性能计数。

本系统使用Redis作为缓存和会话存储层，具体应用包括：AI对话历史的短期记忆存储，利用Redis的String类型配合TTL实现自动过期；Token缓存，存储用户登录令牌；热点数据缓存，缓存热门非遗内容和商品信息。

Redis 6.x引入了多线程IO特性，能够更好地利用多核CPU资源。同时，Redis 7.x引入了Functions功能，提供了更灵活的脚本扩展能力。

## 2.6 AI大语言模型技术概述

人工智能技术的快速发展，特别是大语言模型（Large Language Model，LLM）的突破，为智能应用开发带来了新的机遇。大语言模型是一种基于深度学习技术的自然语言处理模型，它通过海量文本数据的训练，能够理解和生成人类语言[6]。

在AI应用开发中，Prompt工程是一个重要的概念。Prompt是与大语言模型交互的输入内容，良好的Prompt设计能够引导模型产生更准确、更有用的输出。常见的Prompt技术包括：Few-shot Learning（少样本学习），在Prompt中提供少量示例；Chain-of-Thought（思维链），引导模型逐步推理；Role Playing（角色扮演），让模型扮演特定角色。

本系统编写了Omnitrix AI架构，它是一个基于大语言模型的多智能体系统[15]。该系统具有以下特点：多智能体协作，不同的Agent负责不同的功能领域；层次化编排；记忆体系，支持短期记忆、中期记忆、长期记忆和系统记忆四级记忆结构；流式响应，利用Server-Sent Events（SSE）实现实时流式输出。

在模型选择方面，本系统支持多种大语言模型，包括Claude（Anthropic）、DeepSeek（硅基流动）等，能够根据实际需求灵活切换。

## 2.7 本章小结

本章主要介绍了本系统开发所涉及的关键技术，包括后端框架Spring Boot、微服务框架Dubbo+Zookeeper、前端框架Vue.js、数据库MySQL、缓存Redis以及AI大语言模型技术。这些技术构成了本系统的技术基础，为后续的系统设计和实现提供了技术支撑。

# 第3章 系统需求分析

## 3.1 系统需求分析

### 3.1.1 项目概述

本项目旨在设计并实现一个基于Spring Boot的非物质文化遗产管理平台，该平台是一个面向大众的非遗文化服务应用，集成了非遗文化展示、文创商品交易、智能问答服务等功能。

从技术架构角度来看，本系统采用微服务架构，将传统的单体应用拆分为多个独立的服务模块，各模块通过Dubbo RPC进行通信，通过Zookeeper实现服务注册与发现。这种架构能够提高系统的可扩展性、可维护性和容错能力。

从用户角色角度来看，本系统包含三类用户：普通用户（消费者）、管理员（运营人员）和超级管理员。普通用户可以浏览非遗文化内容、购买文创商品、与AI助手进行交互；管理员负责内容管理、订单处理、数据统计等工作；超级管理员拥有系统最高权限，可以进行用户管理、AI开关控制等操作。

### 3.1.2 功能性需求

通过需求调研和分析，本系统的功能性需求主要包括以下几个方面

**用户管理需求**：系统需要支持用户注册、登录、密码找回等功能用户注册时需要填写基本信息，系统对其进行身份验证；用户登录时需要验证账号密码，登录成功后生成Token用于身份标识；用户可以通过绑定的手机号或邮箱找回密码。

**非遗文化展示需求**：系统需要展示非遗项目、传承人、非遗活动等信息。非遗项目需要包含名称、分类、级别、地区、简介、详情等字段；传承人需要包含姓名、头像、技艺特长、代表作品等信息；非遗活动需要包含活动名称、时间、地点、内容简介等信息。用户可以按分类筛选、按关键词搜索、查看详情。

**文创商城需求**：系统需要实现完整的电商功能，包括商品列表、商品详情、商品搜索、购物车、订单创建、订单支付、订单管理等功能模块。商品需要支持多图片展示、库存管理、价格设置；购物车需要支持数量修改、商品删除；订单需要支持状态流转、物流追踪。

**AI智能问答及操作需求**：系统需要提供Omnitrix AI智能助手功能，不仅能够回答用户问题，还能够帮助用户完成各种平台操作。

在智能问答方面，用户可以向AI助手提问关于非遗项目、传承人、技艺特点、活动信息等方面的问题，AI助手能够理解用户意图并给出准确的回答。同时，AI助手还需要具备个性化推荐能力，根据用户的历史行为推荐感兴趣的非遗内容和商品。

在操作执行方面，AI助手能够帮助用户完成以下操作：
- **购物车管理**：搜索商品并加入购物车、从购物车移除商品、修改商品数量、清空购物车
- **订单操作**：查看订单、提交订单、支付订单、取消订单、确认收货
- **内容互动**：点赞/取消点赞、收藏/取消收藏、评论动态、评论活动、报名参加活动
- **信息查询**：查看购物车内容、查看订单列表、查看浏览历史、查看收藏内容、查看收货地址、查看个人资料、查看系统通知
- **地址管理**：设置默认收货地址、删除收货地址

AI助手采用先确认后执行的机制，对于写操作（加入购物车、下单、支付等）会先返回确认提示，待用户确认后再执行，确保操作安全。

**管理后台需求**：系统需要提供功能完善的管理后台，包括内容管理（非遗项目、传承人、活动的增删改查）、商品管理（商品的上下架、库存调整、价格修改）、订单管理（订单查看、发货、退款）、用户管理（用户信息查看、权限分配）、数据统计（销售数据、用户数据、访问数据）等模块。

### 3.1.3 非功能性需求

除了功能性需求外，本系统还需要满足以下非功能性需求

**性能需求**：系统需要能够支持一定规模的并发访问，页面响应时间控制在3秒以内，API接口响应时间控制在1秒以内。AI智能问答需要支持流式输出，首字响应时间控制在3秒以内。

**可用性需求**：系统需要保证7×24小时可用，关键功能需要有容错机制。对于可预见的故障，需要有降级策略，如AI服务不可用时返回预设的FAQ答案。

**安全性需求**：用户密码需要加密存储，敏感操作需要身份验证，API接口需要防止SQL注入、XSS攻击等安全威胁。超级管理员操作需要独立密码验证，防止权限滥用。

**可扩展性需求**：系统采用微服务架构，各服务模块可以独立扩展。AI智能助手采用插件化设计，可以方便地添加新的Agent。数据库设计考虑了未来业务增长的需求。

**易用性需求**：系统界面需要简洁美观、操作便捷，符合用户的使用习惯。关键功能需要有明确引导，错误提示需要友好明确。

## 3.2 系统功能模块

根据需求分析，本系统的功能模块划分为三大类：用户端功能模块、管理端功能模块和AI智能助手模块。

### 3.2.1 用户端功能模块

用户端主要面向普通消费者，功能模块包括：

**账号管理模块**：用户注册与登录（支持密码找回）、个人中心信息管理、个人资料编辑修改等功能。

**非遗文化模块**：非遗文化列表浏览与搜索、非遗文化详情查看与赏析、非遗文化分类筛选等功能。

**传承人模块**：传承人列表浏览查询、传承人详情信息查看、传承人主页作品浏览等功能。

**视频展览模块**：视频展览列表浏览、视频展览详情观看、视频展览收藏管理、视频展览分类筛选等功能。

**文创商城模块**：文创品商城浏览、文创品搜索与筛选、文创品详情查看、购物车管理、商品收藏等功能。

**订单管理模块**：收货地址管理、订单创建与提交、模拟支付流程、我的订单列表查看、模拟物流状态追踪、订单评价功能、订单退货申请等功能。

### 3.2.2 管理端功能模块

管理端主要面向运营人员，功能模块包括：

**用户管理模块**：用户账号管理与权限分配、用户收货地址查看等功能。

**非遗文化管理模块**：非遗文化信息管理与审核、非遗文化类型分类管理、传承人信息管理与维护等功能。

**视频展览管理模块**：视频展览管理与审核、视频展览类型管理、视频展览收藏记录管理等功能。

**文创商城管理模块**：文创品信息管理、文创品类型分类管理、文创品库存管理、文创品属性配置、文创品补货预警列表、文创品收藏记录查看等功能。

**订单管理模块**：订单信息管理与处理、订单评价查看管理、订单退货处理等功能。

**系统管理模块**：系统公告发布与管理、系统数据统计与分析、综合数据分析与可视化、个人信息维护、密码修改与安全管理等功能。

### 3.2.3 AI智能助手模块

Omnitrix AI智能助手是本系统的核心特色功能模块，是一个基于大语言模型（LLM）的多智能体系统，采用类似AutoGPT的Agent架构设计。是基于 Spring Boot + LangChain4j 构建的智能服务中台，专为非物质文化遗产管理平台提供 AI 能力支持。该模块参考Kortex AI的Master Brain + Sub-Agent纯编排架构，实现了智能问答、平台操作执行和智能编排等核心功能。

#### 3.2.3.2 角色分层设计

系统支持三种角色，每种角色拥有独立的Brain实例和差异化工具集：

| 角色 | Brain类 | 工具集 | 用途 |
|------|---------|--------|------|
| 用户 | UserMasterBrain | ContentTools, CommerceTools, UserTools, KnowledgeTools, RecommendTools, BrowseHistoryTools | 普通用户对话、商铺购物、内容浏览、个人中心 |
| 管理员 | AdminMasterBrain | ContentTools, CommerceTools, AdminTools, KnowledgeTools | 内容审批、订单管理、知识库管理、数据统计 |
| 超级管理员 | UltraMasterBrain | UltraTools, SubBrainTools | 系统管理、安全审计、数据分析、子脑编排 |

#### 3.2.3.3 子脑（SubBrain）编排架构

Omnitrix AI系统采用了创新的子脑编排架构，这是系统的核心创新点之一。UltraMasterBrain作为主脑，通过SubBrainTools调用三个独立的子脑（UserSubBrain、AdminSubBrain、UltraSubBrain），每个子脑封装了完整的MasterBrain实例，拥有独立的LLM、工具集和对话记忆。

子脑架构的优势包括：
- **任务解耦**：复杂任务分解为子任务，由不同子脑处理
- **上下文隔离**：子脑使用独立session，避免记忆污染
- **跨用户操作**：支持超级管理员通过子脑操作其他用户数据
- **循环防护**：限制单次请求中子脑调用次数（最多5次）

子脑调用流程：
1. Ultra LLM分析用户请求，识别需要调用的子脑
2. 通过SubBrainTools调用对应子脑
3. 子脑切换到目标用户上下文
4. 子脑执行完整推理（自动多轮Function Calling）
5. 子脑产生的PendingAction传递回主session
6. 恢复主脑上下文，返回结果

#### 3.2.3.4 Function Calling工具系统

系统采用LangChain4j的Function Calling机制实现AI与业务系统的交互。每个工具都是一个标注了@Tool注解的Spring Bean，AI可以自主决定何时调用工具以及调用哪些工具。

**工具注册机制**：
- ToolRegistry：工具注册表，按角色管理工具集
- ToolRegistrationConfig：启动时将工具注册到对应角色

**工具分类**：

| 工具类 | 功能描述 |
|--------|----------|
| ContentTools | 非遗项目搜索、传承人搜索、活动搜索、点赞、收藏、评论、报名 |
| CommerceTools | 商品搜索、购物车管理、订单操作、支付、取消订单 |
| UserTools | 个人信息查询、收货地址管理、资格认证查询、通知查询 |
| KnowledgeTools | 知识库FAQ搜索 |
| RecommendTools | 个性化推荐（基于用户兴趣） |
| BrowseHistoryTools | 浏览历史查询（按时间、按类型） |
| WebSearchTools | 联网搜索（Bing/Google） |
| AdminTools | 内容审批、订单发货、数据统计 |
| UltraTools | 系统管理、用户管理、AI控制 |
| SubBrainTools | 子脑编排调用 |

**工具调用规则**：
- 写操作（加购物车、下单、报名等）必须调用对应工具，不能只用文字回复
- 工具返回结果后，才能告知用户操作状态
- 禁止输出"[操作成功]"前缀，这是系统内部格式

#### 3.2.3.5 记忆体系设计

Omnitrix AI采用四级记忆结构，确保对话的连贯性和上下文理解能力：

**第一级：短期记忆（ChatMemory）**
- 基于LangChain4j的MessageWindowChatMemory
- 存储最近20轮对话内容
- 支持从Redis/MySQL预加载历史消息

**第二级：中期记忆（摘要）**
- MemorySummarizer定期将长对话压缩为摘要
- 当对话轮数超过阈值时触发摘要
- 摘要存储到Redis，支持快速恢复

**第三级：长期记忆（持久化）**
- MemoryExtractor从对话中提取用户偏好、兴趣等信息
- 持久化到MySQL数据库
- 构建用户画像，注入到每次对话

**第四级：系统记忆（角色设定）**
- 通过@SystemMessage注解定义
- 包含角色定义、工具使用规则、回答规范等

#### 3.2.3.6 动态Skill加载系统

系统实现了Skill动态加载机制，根据用户消息内容按需选择激活的Skill：

- SkillSelector：分析用户消息，选择匹配的Skill
- SkillPromptConfig：管理Skill集合和提示词模板
- 动态注入到Brain的system message中

这种设计使AI能够：
- 根据上下文动态加载所需能力
- 减少不必要的token消耗
- 支持插件化扩展新能力

#### 3.2.3.7 安全与保障机制

**Guardrails安全过滤**：
- 输入Guardrails：检测用户输入中的敏感词、恶意指令
- 输出Guardrails：过滤AI输出中的不当内容

**Token预算管理**：
- 每日/每月token限额
- 超出限额时返回友好提示
- 支持不同角色设置不同限额

**限流保护**：
- 基于Redis的分布式限流
- 支持按用户、按IP多维度限流
- 熔断器模式：连续失败时自动熔断

**用户AI开关**：
- 管理员可禁用特定用户的AI功能
- 支持设置禁用原因
- 可配置自动恢复时间

#### 3.2.3.8 流式响应与多模态支持

**SSE流式输出**：
- 首字响应时间<3秒
- 支持实时打字机效果
- 支持thinking过程展示

**多模态支持**：
- 支持图片/文件上传
- 调用多模态模型（如Claude vision）
- 自动提取图片内容进行问答

#### 3.2.3.9 核心技术栈

| 类别 | 技术选型 |
|------|----------|
| 核心框架 | Spring Boot 3.x |
| AI框架 | LangChain4j 0.35.0 |
| LLM提供商 | SiliconFlow（DeepSeek等）、Anthropic Claude |
| 流式输出 | Server-Sent Events (SSE) |
| 缓存 | Redis |
| 消息队列 | Dubbo |
| 配置中心 | Nacos |
| 监控 | Prometheus + Micrometer |

本AI模块的设计参考了业界先进的Agent架构，如AutoGPT的自主Agent思路、Kortex AI的Master-SubAgent编排模式，以及LangChain4j的Function Calling能力，实现了具有自主知识产权的多智能体系统。

## 4.1 系统总体功能设计

### 4.1.1 系统架构设计

本系统采用微服务架构设计，整体架构分为四个层次：接入层、服务层、数据层和基础设施层。

**接入层**：负责处理用户请求，包括前端Web应用和移动端应用。前端采用Vue.js框架，通过HTTP API与后端进行交互。

**服务层**：是系统的核心业务逻辑层，包含多个微服务模块。本系统包含以下微服务：ich_user_provider（用户服务）、ich_content_provider（内容服务）、ich_omnitrix（AI智能服务）、ich_user_web（用户端API网关）、ich_admin_web（管理端API网关）。各服务之间通过Dubbo RPC进行通信。

**数据层**：负责数据的持久化存储，包括MySQL数据库和Redis缓存。MySQL存储业务数据，Redis用于缓存和会话管理。

**基础设施层**：提供系统运行所需的基础设施支持，包括Zookeeper（服务注册与发现）、Nacos（配置中心，可选）、Tomcat（Web容器）等。

### 4.1.2 微服务模块划分

根据业务边界，本系统将功能划分为以下微服务模块：

**ich_common**：公共基础模块，提供通用工具类、常量定义、枚举类、自定义异常等，被所有其他模块依赖。

**ich_interface**：Dubbo服务接口定义模块，定义各服务的接口和DTO，被服务提供者和消费者共同依赖。

**ich_user_provider**：用户服务提供者，负责用户注册、登录、认证、收货地址、浏览历史等功能的实现。

**ich_content_provider**：内容服务提供者，负责非遗项目、传承人、视频展览、商品、订单等内容的业务逻辑处理。

**ich_omnitrix**：AI智能服务提供者，是Omnitrix AI系统的核心模块，负责智能问答、推荐引擎、意图识别等AI功能的实现。

**ich_user_web**：用户端API接入层，提供用户端的RESTful API接口。

**ich_admin_web**：管理端API接入层，提供管理端的RESTful API接口。

各模块的端口分配如下：ich_user_provider（8081）、ich_content_provider（8082）、ich_omnitrix（8083）、ich_user_web（8084）、ich_admin_web（8085）。

### 5.2.1 登录注册实现

用户登录功能是系统的入口模块，涉及到用户身份验证和会话管理。

用户注册时，系统接收用户提交的注册信息，包括用户名、密码、昵称、手机号、邮箱等。首先对输入进行合法性校验，然后对密码进行BCrypt加密处理，最后将用户信息存入数据库。注册成功后，系统自动登录并返回用户信息和Token。

用户登录时，系统接收用户名和密码，首先查询用户是否存在，然后使用BCrypt验证密码是否正确。验证通过后，系统生成JWT Token作为登录凭证，并将Token和用户信息返回给前端。Token的有效期为24小时，前端在后续请求中携带Token进行身份验证。

登录功能的核心代码如下：

```java
@RestController
@RequestMapping("/api/user")
public class UserController {
    
    @Autowired
    private UserService userService;
    
    @PostMapping("/login")
    public Result<LoginVO> login(@RequestBody LoginDTO loginDTO) {
        // 参数校验
        if (StringUtils.isEmpty(loginDTO.getUsername()) 
            || StringUtils.isEmpty(loginDTO.getPassword())) {
            return Result.error("用户名和密码不能为空");
        }
        
        // 查询用户
        User user = userService.getUserByUsername(loginDTO.getUsername());
        if (user == null) {
            return Result.error("用户不存在");
        }
        
        // 验证密码
        if (!passwordEncoder.matches(loginDTO.getPassword(), user.getPassword())) {
            return Result.error("密码错误");
        }
        
        // 检查用户状态
        if (user.getStatus() == 0) {
            return Result.error("账号已被禁用");
        }
        
        // 生成Token
        String token = jwtUtil.generateToken(user.getId());
        
        LoginVO loginVO = new LoginVO();
        loginVO.setToken(token);
        loginVO.setUserId(user.getId());
        loginVO.setUsername(user.getUsername());
        loginVO.setNickname(user.getNickname());
        
        return Result.success(loginVO);
    }
}
```

商品购买功能的核心实现代码如下：

```java
@Service
public class OrderServiceImpl implements OrderService {
    
    @Autowired
    private OrderMapper orderMapper;
    
    @Autowired
    private ProductMapper productMapper;
    
    @Autowired
    private RedisTemplate<String, Object> redisTemplate;
    
    @Override
    @Transactional(rollbackFor = Exception.class)
    public Order createOrder(OrderCreateDTO createDTO) {
        // 1. 校验商品库存
        List<OrderItem> orderItems = new ArrayList<>();
        BigDecimal totalAmount = BigDecimal.ZERO;
        
        for (CartItemDTO cartItem : createDTO.getItems()) {
            Product product = productMapper.selectById(cartItem.getProductId());
            if (product == null) {
                throw new BusinessException("商品不存在: " + cartItem.getProductId());
            }
            if (product.getStock() < cartItem.getQuantity()) {
                throw new BusinessException("商品库存不足: " + product.getName());
            }
            
            // 计算小计
            BigDecimal itemAmount = product.getPrice().multiply(
                new BigDecimal(cartItem.getQuantity())
            );
            totalAmount = totalAmount.add(itemAmount);
            
            // 构建订单项
            OrderItem item = new OrderItem();
            item.setProductId(product.getId());
            item.setProductName(product.getName());
            item.setProductPrice(product.getPrice());
            item.setQuantity(cartItem.getQuantity());
            orderItems.add(item);
            
            // 冻结库存（扣减库存）
            productMapper.decrementStock(product.getId(), cartItem.getQuantity());
        }
        
        // 2. 创建订单
        Order order = new Order();
        order.setOrderNo(generateOrderNo());
        order.setUserId(createDTO.getUserId());
        order.setTotalAmount(totalAmount);
        order.setPayAmount(totalAmount);
        order.setStatus(OrderStatus.PENDING_PAY.getCode());
        order.setReceiverName(createDTO.getReceiverName());
        order.setReceiverPhone(createDTO.getReceiverPhone());
        order.setReceiverAddress(createDTO.getReceiverAddress());
        
        orderMapper.insert(order);
        
        // 3. 保存订单项
        for (OrderItem item : orderItems) {
            item.setOrderId(order.getId());
            orderItemMapper.insert(item);
        }
        
        // 4. 清空购物车
        String cartKey = "cart:" + createDTO.getUserId();
        redisTemplate.delete(cartKey);
        
        return order;
    }
}
```

## 5.4 AI智能问答实现

### 5.4.1 Omnitrix AI系统架构

Omnitrix AI是本系统的核心特色模块，它是一个基于大语言模型的多智能体系统，参考了AutoGPT的自主Agent思路和Kortex AI的Master-SubAgent纯编排架构。系统的整体架构分为以下几个层次：

**接入层（API Layer）**：
- AiChatController：处理用户端的AI对话请求
- 支持同步聊天、流式聊天（SSE）、多模态聊天三种模式
- 提供对话管理、反馈收集等辅助接口

**编排层（Orchestrator Layer）**：
- OrchestratorService是核心编排器，负责处理用户请求的完整流程
- 包含路由选择、降级处理、限流熔断、SSE流式输出、Token预算管理、安全过滤等功能
- 支持PendingAction机制，实现"先确认后执行"的操作安全

**大脑层（Brain Layer）**：
- MasterBrainFactory工厂类负责动态构建Brain实例
- 根据角色（user/admin/ultra）注入不同的工具集和记忆
- UserMasterBrain、AdminMasterBrain、UltraMasterBrain三个接口定义不同角色的AI能力

**工具层（Tools Layer）**：
- 采用LangChain4j的@Tool机制实现Function Calling
- ToolRegistry按角色管理工具集
- 包含ContentTools、CommerceTools、UserTools、KnowledgeTools等业务工具
- SubBrainTools实现子脑编排调用

**子脑层（SubBrain Layer）**：
- UserSubBrain、AdminSubBrain、UltraSubBrain封装独立的Brain实例
- 支持跨用户操作、上下文隔离、任务分解
- 通过PendingAction传递机制与主脑协同工作

**基础设施层（Infrastructure Layer）**：
- LLM集成：支持SiliconFlow和Anthropic Claude两种提供商
- 记忆系统：ChatMemoryManager管理短期、中期、长期记忆
- Skill系统：SkillSelector动态加载所需技能
- 监控追踪：TelemetryTracer实现全链路追踪

### 5.4.2 智能问答流程

用户向AI助手提问时，系统按照以下流程处理：

**第一步，输入安全检查**。系统使用GuardrailsFilter对用户输入进行安全过滤，检测敏感词、注入攻击等安全威胁。同时检查用户AI访问权限和Token预算。

**第二步，PendingAction处理**。检查用户是否有待确认的操作（如加入购物车、下单等），如有则询问用户确认或取消。

**第三步，Brain构建与调用**。根据用户角色（user/admin/ultra）构建对应的MasterBrain实例，注入该角色可用的工具集、对话记忆和动态Skill。

**第四步，Function Calling执行**。LLM根据对话内容自主决定是否调用工具，以及调用哪些工具。系统支持多轮Function Calling，工具返回结果后LLM会继续推理直到生成最终回答。

**第五步，输出安全过滤**。GuardrailsFilter对AI输出进行安全过滤，确保返回内容安全无害。

**第六步，后处理**。异步执行记忆保存、对话摘要生成、用户画像更新、Token预算扣减等操作。

智能问答的核心实现代码如下：

```java
@Service
public class OrchestratorService {
    
    private final MasterBrainFactory masterBrainFactory;
    private final GuardrailsFilter guardrailsFilter;
    private final TokenBudget tokenBudget;
    private final ActionExecutor actionExecutor;
    
    /**
     * 同步聊天入口
     */
    public ChatResponse chat(Long userId, String sessionId, String userMessage) {
        // 1. 检查用户AI访问权限
        String accessDenied = checkUserAiAccess(userId);
        if (accessDenied != null) {
            return ChatResponse.of(null, sessionId, accessDenied, "system", 0);
        }
        
        // 2. 检查Token预算
        if (tokenBudget.isBudgetExceeded(userId)) {
            return ChatResponse.of(null, sessionId, "您今日的AI对话额度已用完", "budget", 0);
        }
        
        // 3. 获取或创建对话
        AiConversation conversation = conversationService.getOrCreate(sessionId, userId);
        
        // 4. 处理待确认操作
        ChatResponse pendingResponse = handlePendingActionSync(userId, sessionId, userMessage, conversation);
        if (pendingResponse != null) {
            return pendingResponse;
        }
        
        // 5. 构建Brain并调用（含降级链）
        String role = determineRole(userId);
        BrainResult result = invokeBrainSync(role, userId, sessionId, userMessage);
        
        // 6. 保存和后处理
        AiMessage assistantMsg = saveAndPostProcess(
                conversation, sessionId, userId, userMessage, result.content,
                result.model, role, 0, result.inputTokens, result.outputTokens);
        
        return ChatResponse.of(assistantMsg.getId(), sessionId, result.content, result.model, 0);
    }
    
    /**
     * 同步调用Brain，含降级链
     */
    private BrainResult invokeBrainSync(String role, Long userId, String sessionId, String userMessage) {
        String skills = masterBrainFactory.buildDynamicSkillsPrompt(userMessage);
        String primaryModel = llmProperties.getPrimaryConfig().getModel();
        
        try {
            // 尝试主模型
            Result<String> result = invokeBrainPrimary(role, userId, sessionId, userMessage, skills);
            return new BrainResult(result.content(), primaryModel, 
                    result.tokenUsage().inputTokenCount(), 
                    result.tokenUsage().outputTokenCount());
        } catch (Exception primaryEx) {
            // 主模型失败，尝试降级到辅助模型
            log.warn("主模型调用失败，尝试降级: {}", primaryEx.getMessage());
            Result<String> fallbackResult = invokeBrainFallback(role, userId, sessionId, userMessage, skills);
            return new BrainResult(fallbackResult.content(), 
                    llmProperties.getAuxiliaryConfig().getModel() + "(fallback)",
                    fallbackResult.tokenUsage().inputTokenCount(),
                    fallbackResult.tokenUsage().outputTokenCount());
        }
    }
    
    /**
     * 主模型调用 - 根据角色构建对应Brain
     */
    private Result<String> invokeBrainPrimary(String role, Long userId, String sessionId,
                                               String userMessage, String skills) {
        switch (role) {
            case "user": {
                var brain = masterBrainFactory.buildUserBrain(userId, sessionId);
                String profile = masterBrainFactory.buildUserProfile(userId);
                return brain.chat(userMessage, skills, profile);
            }
            case "admin": {
                var brain = masterBrainFactory.buildAdminBrain(sessionId);
                return brain.chat(userMessage, skills);
            }
            case "ultra": {
                var brain = masterBrainFactory.buildUltraBrain(sessionId);
                return brain.chat(userMessage, skills);
            }
            default:
                throw new IllegalArgumentException("Unknown role: " + role);
        }
    }
}
```

流式响应使用Server-Sent Events（SSE）技术，实现代码如下：

```java
@GetMapping(value = "/chat/stream", produces = MediaType.TEXT_EVENT_STREAM_VALUE)
public SseEmitter chatStream(@RequestParam String sessionId,
                              @RequestParam String message,
                              @RequestParam Long userId) {
    SseEmitter emitter = sseEmitterManager.create();
    
    // 异步执行流式输出
    agentExecutor.execute(() -> {
        try {
            TokenStream tokenStream = buildTokenStream(role, modelCode, userId, sessionId, message, skills);
            tokenStream.onChunk(chunk -> {
                // 处理thinking标签
                if (chunk.contains("<think>")) {
                    sseEmitterManager.sendThinking(emitter, extractThinking(chunk));
                } else {
                    sseEmitterManager.sendChunk(emitter, chunk);
                }
            })
            .onComplete(response -> {
                // 完成处理
                sseEmitterManager.sendDone(emitter, messageId, latencyMs, model);
            })
            .onError(error -> {
                // 错误处理
                sseEmitterManager.sendError(emitter, "AI服务暂时不可用");
            })
            .start();
        } catch (Exception e) {
            sseEmitterManager.sendError(emitter, "AI服务暂时不可用");
        }
    });
    
    return emitter;
}
```

### 5.4.3 个性化推荐实现

个性化推荐功能基于用户的历史行为数据，利用协同过滤和内容相似度算法，为用户推荐感兴趣的非遗内容和文创商品。

推荐系统的数据来源包括：用户的浏览历史、购买记录、收藏记录、咨询记录、浏览历史等。系统从这些数据中提取用户的偏好特征，如感兴趣的分类、关注的项目类型、价格偏好等。

推荐算法采用混合推荐策略，结合基于内容的推荐和协同过滤推荐。基于内容的推荐根据用户偏好与内容的相似度进行推荐；协同过滤推荐根据相似用户的行为进行推荐。

系统通过RecommendTools工具封装推荐能力，AI助手可以根据用户需求调用该工具获取个性化推荐结果。推荐内容会在对话中展示给用户，并提供收藏功能方便用户后续查看。

本系统的创新点主要体现在以下几个方面：第一，将微服务架构应用于非遗文化管理领域，提高了系统的可扩展性和可维护性；第二，将AI大语言模型技术与传统文化传播相结合，实现了智能化的用户服务体验；第三，构建了多智能体协作的AI系统架构，支持复杂场景下的智能问答和任务处理。
